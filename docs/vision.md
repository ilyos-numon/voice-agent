# voice-agent — 완성된 모습

> 이 문서는 "어떻게 만들까"가 아니라 "다 만들어졌을 때 사용자가 무엇을 보고 겪는가"를 적는다.
> 내부 구조는 docs/decisions.md 에서 다룬다.
> 원본은 회사에서 public kiosk client를 위해 만든 시스템이고, 여기서는 공개 데이터로 처음부터 다시 만든다.
> 1차(키오스크 음성비서)는 완료됐다. 이 문서는 2차 방향: **투명한 음성 에이전트 빌더**. 1차 문서는 git 기록에 있다.

## 한 문장

내 문서를 붙여 넣으면 1분 안에 말하는 상담원이 되고, 매 답변마다 "몇 초 걸렸고 어느 문장을 근거로 답했는지"가 보이며, 버튼 하나로 성적표까지 나온다.

## 왜 이게 다른가

음성 에이전트 빌더는 이미 많다. 대부분 내부를 숨긴다. 이 앱은 반대로 **속을 보여준다**.
- 지연: 매 턴 STT·검색·LLM·TTS 단계별 시간과 첫 음성까지 시간.
- 근거: 답의 문장마다 어느 문서 조각에서 왔는지. 근거가 없으면 "모른다"고 말한다.
- 품질: 내 문서로 질문을 자동으로 만들어 내 에이전트를 시험한 성적표.

## 등장인물

| 역할 | 상황 | 바라는 것 |
|---|---|---|
| 써보는 사람 (가게 사장·사내 담당자·개발자) | 링크 하나로 들어왔다, 회원가입은 싫다 | 내 FAQ로 음성 상담원이 되는지 5분 안에 보고 싶다 |
| 포트폴리오를 읽는 엔지니어·채용 담당자 | 레포를 5분 본다 | 병목을 어떻게 찾고 줄였는지, 환각을 어떻게 막는지 숫자로 보고 싶다 |
| 재현하는 사람 | 레포를 클론해 명령 몇 개 돌린다 | 같은 숫자가 나와야 믿는다 |

## 시나리오 1: 프리셋으로 바로 체험 (30초)

화면은 두 장이다. 스튜디오 `/studio` → 상담원 작업 공간 `/studio/app?agent=<id>`. 옛 주소 `/`·`/talk`는 같은 쿼리를 붙인 채 새 주소로 리다이렉트된다.

1. 첫 화면(`/studio`)의 "바로 체험하기"에 카드 4장: 민원 키오스크 · 식당 주문 안내 · 병원 접수 안내 · 사내 규정 Q&A. 카드마다 예시 질문 하나가 보인다.
2. "민원 키오스크" 카드를 누르면 바로 대화 화면(`/studio/app?agent=preset-civil-kiosk`). 큰 🎤 버튼을 누르고 "등본 떼려면 뭐 필요해요?" 말한 뒤 다시 누른다. 마이크가 없으면 글자 칸에 쓰고 "묻기", 또는 예시 질문 버튼을 누른다.
3. 1초 안팎에 목소리가 시작되고, 화면에 자막·출처·이번 턴의 지연 막대가 뜬다.

## 시나리오 2: 내 상담원 만들기 (60초 셋업)

1. 같은 첫 화면(`/studio`) 아래 "내 상담원 만들기" 폼에서 세 칸만 채운다.
   - **무엇을 아나요**: "자료 종류"에서 "글 붙여 넣기" 또는 "자주 묻는 질문 표(CSV)"(`질문,답변` 두 열) 업로드.
   - **어떤 성격인가요**: 이름, 말투(친절하게 / 간결하게), 목소리(기본 음색 중 선택).
   - **어떻게 답하나요**: 답 길이(한 문장 / 짧게 / 자세히), 모르는 질문일 때(“모른다”고 말하기 / 담당자 안내 문구), 피할 주제(자유 입력).
2. 설정 화면에는 엔진 용어가 없다. top-k·temperature 대신 "답을 얼마나 짧게", "모르면 어떻게".
3. "상담원 만들기"를 누르면 몇 초 안에 대화 화면(`/studio/app?agent=<id>`)으로 넘어간다. 자료에 문제가 있으면 폼 아래에 이유가 뜨고 페이지는 그대로다.
4. 대화 화면 위 "공유 링크 복사"를 누르면 `/studio/app?agent=<id>` 링크가 복사된다. 링크를 연 사람은 첫 화면을 거치지 않고 같은 상담원 대화 화면으로 바로 들어온다. 24시간이 지나 사라진 상담원이면 안내와 "새 상담원 만들기" 링크가 뜬다.

## 시나리오 3: 투명 모드 — 매 턴 영수증

대화 화면(`/studio/app`)에서는 답마다 "영수증 — 이번 답이 어떻게 나왔나"가 펼쳐진 채 붙는다. 제목을 누르면 접히고 자막만 남는다.

```
👤 "주차 돼요?"
🔊 네, 건물 지하 1층에 2시간 무료 주차가 됩니다.¹ 이후 30분당 1,000원입니다.¹
   ¹ 근거: FAQ 12 "주차 안내" — "지하 1층 2시간 무료, 이후 30분당 1,000원"

 ⏱ 듣기 1.1s ┤검색 3ms┤ 생각 0.8s ┤ 말하기 시작 0.4s │ 첫 음성까지 2.3s
 🔎 검색 후보: #12 주차 안내 (점수 8.1) · #4 오시는 길 (3.2) · #9 영업시간 (1.0)
```

- 영수증 안: 단계별 시간 막대와 첫 음성까지, 문장별 근거 각주, "찾아본 자료" 후보와 점수.
- 근거와 맞지 않는 문장은 표시가 달라진다(근거 없음 경고).
- 근거 문서가 없으면 지어내지 않고 설정한 "모를 때" 문구로 답한다.

## 시나리오 4: 성적표 — 직접 말 안 해봐도 쓸 만한지 안다

1. 대화 화면 아래 "성적표" 탭에서 "질문 수"를 고르고 "시험해보기"를 누르면 내 문서로 질문(최대 30개)을 자동으로 만든다(원문 그대로 + 사람 말투로 바꾼 것). 진행 상황이 탭 안에 표시된다.
2. 질문을 음성으로 합성해 내 상담원에 실제로 묻는다.
3. 2~3분 뒤 성적표:

```
 내 상담원 성적표 — 질문 30개
 맞는 근거를 찾음    27 / 30   (글자 질문 29 / 음성 질문 27)
 첫 음성까지         p50 1.4s · p95 2.6s
 틀린 3개            "주차 되나여"→ #4 오시는 길 (음성 인식 오류) ...
 개선 힌트           FAQ 4와 12가 비슷합니다. 질문을 더 구체적으로 적으면 좋아집니다.
```

## 시나리오 5: A/B — 설정을 바꾸면 무엇이 달라지나

1. 대화 화면 아래 "설정 비교(A/B)" 탭에서 "비교할 질문"(기본은 방금 물은 질문)과 "A 답 길이"·"B 답 길이"를 고르고 "비교하기". 예: 짧게 vs 자세히. 요약 켬 vs 끔은 이번 화면에 없고 API로 비교한다.
2. 두 답이 A·B 두 칸에 나란히 뜬다. "A 듣기"·"B 듣기"로 이어서 듣고, 첫 음성까지 시간·답 길이·근거를 옆에 놓고 본다.
3. "요약을 켜면 1.2초 늦게 시작하지만 답이 3문장으로 줄어든다" 같은 결론을 사용자가 직접 얻는다.

## 시나리오 6: 읽는 사람·재현하는 사람

- README 첫 줄: "투명한 음성 에이전트 빌더". 그 아래 지연 폭포 그림과 표(1차 결과 유지).
- 성적표도 명령 하나로 재현된다(프리셋 하나에 대해 같은 숫자).

## 지키는 것

- **음성은 서버 밖으로 나가지 않는다.** STT·TTS는 서버 안에서 돈다. 요약을 켰을 때만 질문 문장과 근거 조각이 LLM API로 간다.
- 올린 문서는 그 상담원에만 쓰고, 정해진 시간(기본 24시간) 뒤 지운다. 계정 없음.
- 공개 운영을 위해: 상담원당 문서 크기 상한, 세션당 질문 수 상한, 동시 요청이 몰리면 대기열("앞에 2명") 표시. 기본은 요약 꺼짐.

## 단계 나누기

- **2차 MVP (완료)**: 백엔드와 API 계약. 상담원 만들기(텍스트·CSV) · 대화(기존 스트리밍 재사용) · 투명 모드 데이터(단계별 지연, 문장별 근거, 검색 후보) · 성적표 · A/B · 프리셋 4개. 기존 `app/static` 데모 페이지는 이 기능을 확인하는 최소 화면으로만 고친다(E2E 스크린샷용).
- **3차 (이번)**: 두 페이지 화면(만들기 `/` → 대화 `/talk`), 바닐라 JS — 이 태스크에서 구현.
- **4차**: 공개 URL 배포 (프론트엔드 이후).

## "됐다"고 말할 수 있는 순간

- 처음 보는 사람이 CSV 하나 붙여 1분 안에 자기 상담원과 말로 대화한다.
- 매 답변에 지연과 근거가 보이고, 근거 없는 질문엔 지어내지 않는다.
- 성적표 숫자가 명령 하나로 다시 나온다.
- 프론트엔드를 만드는 사람이 API 문서만 보고 화면을 붙일 수 있다.
